## 2. 剪輯規則

### 2.1 節奏（scene detection 實測）

| | A | B |
|---|---|---|
| 鏡頭數 | 34 | 21 |
| 平均鏡長 | **1.62s** | **2.17s** |
| 中位鏡長 | **1.43s** | **1.87s** |
| 四分位 (p25–p75) | 1.17–1.79s | 1.45–3.30s |
| 最短／最長 | 0.33s / 3.77s | 1.1s / 4.2s |
| <1s 的鏡頭 | 6 (18%) | 1 (5%) |
| ≥3s 的鏡頭 | 3 (9%) | 7 (33%) |

**規則：**

- **預設鏡長 1.2–1.8s**，這是兩支的主體（A 有 21/34、B 有 13/21 落在 1–2s）。
- **不要等長切**。A 的鏡長序列是 `2.3 3.4 1.2 1.7 0.8 1.8 1.2 1.2 0.7 0.8 1.6 1.8…`，長短交錯。避免連續三鏡同長。
- **「呼吸鏡」節流**：每 8–12 鏡插一個 2.8–4.2s 的長鏡（風景、全景、小孩專注在做事）。A 在 25.9s / 28.7s / 48.1s，B 在 6.5s / 10.0s / 20.9s / 36.9s。
- **A 型（家庭）比 B 型（攻略）快約 35%**。資訊量大的段落要放慢，讓觀眾讀得完字幕。
- 首鏡 1.5–2.3s，尾鏡 1.2–3.2s，都不是最短鏡。

### 2.2 轉場：**全部是硬切，一個轉場特效都沒有**

逐幀 diff 驗證（25.9s / 12.4s / 44.3s 三處切點）：差值序列是 `0.012 0.012 0.012 → 0.546 → 0.014 0.015`，**單幀尖峰、無斜坡**。

沒有 crossfade、沒有 fade-to-black、沒有 slide、沒有 zoom/whip 轉場、沒有黑底字卡（blackdetect 全片 0 命中；contact sheet 上看起來黑的格子都是實拍暗場景）。

> **這直接推翻專案現在的預設。** `edl.schema.json` 的 `transition_out` 有 `crossfade / fade-black / slide`，`Montage.tsx` 也實作了 crossfade 重疊。若要對齊這個模板，**`transition_out` 一律 `cut`**，crossfade 只保留給「同場景不同時間」的少數情況。

### 2.3 同鏡跳接（jump cut）

A 的音軌在 4.154–4.235s 與 5.007–5.068s 有 **0.06–0.08s 的數位靜音**，前後畫面同場景。這是**把同一鏡裡的廢話剪掉留下的接縫**——一鏡之內再切 2–3 刀，只留重點字詞。

節奏感有一半來自這個，不是來自換鏡頭。

### 2.4 開場鉤子（A 的招牌手法，值得抄）

```
0.00 – 1.23s   畫面：走路中的主角（動態、有方向感）
               字幕：「我們要去…」  ← 刻意留刪節號
               聲音：現場音 + 音樂
1.23 – 1.54s   ★ 0.30s 完全數位靜音（振幅 = 0，不是淡出）★
1.54s –        字幕替換成「台北」，音樂／現場音同時回來
2.30s          第一刀
```

`silencedetect` 實測：`silence_start: 1.31 / silence_end: 1.66`；逐樣本零值區間 **1.232–1.535s**。

**規則：0–2.5s 內先拋懸念，在揭曉前放一段 0.25–0.35s 的絕對靜音，揭曉幀同時恢復聲音。**

B 用另一種開場：**第 0 秒就直接給最好看的畫面**（小孩滑雪下坡的全景），標題疊在上面，不留懸念。適合攻略型。

### 2.5 段落與結尾

- **段落切換靠字卡，不靠轉場**。A 用 `★第二天 早上★` 這種置頂字卡當分隔（19% 高度），畫面照樣硬切。
- **結尾（A）**：收尾台詞（「我們要回家囉！」）→ 切到**全家合照的拍立得卡**，定格 0.6s 到片尾。聲音**不淡出**，硬停。
- **結尾（B）**：最後一句 CTA（「這邊很好玩的推薦給你們！」）在 42–44.6s，之後**最後 3.2s 完全沒有字**，純畫面（小孩在雪地玩）+ 音樂收尾，音量從 -19 dB 滑到 -25 dB 軟淡出。
- 共同點：**最後一鏡不放資訊，留一個「呼吸」畫面**。

### 2.6 照片的用法

- A 只用了 **2 張照片**（11.53–12.43s 的 0.9s、54.40–55.00s 的 0.6s），B **一張都沒有**。
- **照片完全靜止，沒有 Ken Burns**（逐幀 diff = 0.000）。
- 照片以**拍立得卡**呈現：米白紙質背景（≈ `#F2F0EB`）鋪滿全幀，照片**旋轉約 -4°**、帶柔和投影，不滿版。
- 照片上可手寫粉紫色字 + ♡ 塗鴉（A 的片尾合照）。

> **又一條和專案現況相反的規則。** 專案 `KenBurnsPhoto` 預設 `to: [0.5,0.5,1.1]`（永遠推 10%）。這個模板要的是 `effect: "none"` + 拍立得外框。照片在這種片型裡是**標點符號**，不是主體，比例應 ≤ 5%。

### 2.7 隱私處理

小孩正臉用**墨鏡 emoji 貼紙**或**局部模糊**蓋掉（A 的 0.6s、52.5s、片尾合照都有）。這是作者的固定習慣，做成可選的 EDL 欄位比較好。

## 3. 字幕系統

這是兩支片的核心，也是專案目前**完全沒有**的一層（`Montage.tsx` 只有 `Title` 的 3 種 style，沒有字幕軌）。

### 3.1 四層文字，用途分明

| 層 | 用途 | 樣式 | 位置 | 字級（佔寬） |
|---|---|---|---|---|
| **L1 章節標** | 段落分隔、梗標 | 白字 + 黑描邊，前後包 `★` | **固定 19%H**、置中 | ~5.5% |
| **L2 主字幕** | 作者旁白／吐槽／品名 | 白字 + **粉紅描邊**（A）／白字 + 黑描邊（B） | A：**自由手放**；B：**固定 75–79%H** | 5.5–6.5% |
| **L3 逐字稿** | 現場對話的英文翻譯 | 細白無襯線、**無描邊** | 跟著主字幕下方或就近避開主體 | ~5.5% |
| **L4 強調字** | 情緒爆點、價格、數字 | 白字 + **橘紅雙層粗描邊** | 置中 43–48%H | **11–12%**（約 L2 的 2 倍） |

### 3.2 各層細節

**L1 章節標**

```
★做好 直接開玩★        （25.5s）
★小孩最喜歡的飯店早餐★  （36.5s）
★第二天 早上★          （33s）
★自己動手做玩具★        （21s）
```

- 固定格式：`★` + 半形空格 + 文字 + `★`
- 圓潤黑體（接近「思源黑體 Heavy」或「Noto Sans TC Black」），黑描邊約 3–4px
- 置頂 19%H，避開 IG 頂部 UI

**L2 主字幕**

- A 用**粉紅描邊白字**（`妹妹是神射手？!`、`好吃`、`萬豪牛肉麵`）當「作者的聲音」，**黑描邊白字**當中性敘述（`景色超好`、`說飯店掰掰`）。兩種顏色是**語氣的區分**，不是隨機。
- A 的垂直位置實測：30%、53%、62%、70%、72% — **每鏡手動避開主體**，不是固定下三分。
- B 全部走**固定底部帶**：y ≈ 75–79%H，置中，白字細黑描邊（Noto Sans TC Medium 質感）。
- **B 的字幕換行頻率 ≈ 3.4s 一句**（47.8s / 14 句），比鏡頭切換慢——**一句字幕跨 1–2 鏡**。不要一鏡一句。

**L3 逐字稿**

- 只有 A 有（`eight`、`one`、`two`、`right?`、`Oh My God`、`Zuoying to Taipei`）。
- 對應**小孩講話的片段**，是給國際觀眾的翻譯層。
- 旁邊偶爾加**手繪塗鴉**（`//` 短斜線、箭頭），白色、線條粗細約 4px。

**L4 強調字**

- `超級好玩！`（B 27.5s）、`七萬七日幣`（B 23s）。
- 實測有**持續脈動動畫**：bbox 寬在 175→271px 之間來回，週期約 0.6–0.7s，中心固定。是 CapCut 那種「心跳」循環，不是一次性彈入。
- 出現時**底部字幕照常存在**，兩層同時在畫面上。

### 3.3 其他疊加元件

**位置膠囊**（A 6.5s）

- 米白圓角膠囊，`📍` + 台灣地圖小圖示 + `高鐵`（橘褐粗體）+ `左營站`（深褐）
- 兩段配色不同：**類別用橘、專名用深褐**
- 位置：上方約 25%H，靠左

**黃色地點徽章**（A 12–13s）：`台北 飯店`，黃底圓角，字較小，用於次要地點標註。

**直排清單貼紙**（B 12.5s）

- `雪衣 / 雪褲 / 手套 / 眼鏡` 直排兩欄，綠描邊黑字
- 配一個**手繪白色 `>>>` 箭頭**指向畫面中的實物
- 用途：把畫面裡的東西「點名」

## 4. 音樂與聲音

| | A | B |
|---|---|---|
| Integrated | -15.0 LUFS | -14.3 LUFS |
| **LRA** | **12.2 LU** | **4.3 LU** |
| True peak | +0.3 dBFS | +2.3 dBFS |
| 低頻 <250Hz 佔比 | 11.6% | 17.8% |
| 中頻 250–4k | 72.3% | 59.2% |
| 高頻 >4k | 16.2% | 23.1% |
| 音樂床連續度 | 80% | 91% |
| 音節率調變 (3–8Hz) | 35.4% | 45.9% |

**讀法：**

- **兩支都有人聲**（音節率調變顯著）。A 是**現場同期聲**（中頻 72%，LRA 12.2 = 忽大忽小的真實收音）；B 是**後配旁白**（LRA 4.3 = 壓過、很平，底部字幕就是旁白逐字稿）。
- **音樂是「床」不是「拍」**：onset 自相關峰值只有 0.10–0.14 且在 60–190 BPM 之間完全平坦 → **沒有明顯節拍**。
- 因此 **剪點不卡拍**，是**卡語意／卡動作**。鏡長分佈不規則也印證這點。
- 音樂全程鋪底（80–91% 時間），**在人講話時壓低**（A 的 RMS 在 -20 ～ -29 dB 之間擺盪就是 ducking 的痕跡）。專案 `Bgm` 的 `duckUnderSpeech` 壓到 **0.3×** 大致對，可以再細一點：**說話時 -12 dB，句間 1.5s 內不回升**。
- 尾巴：A 硬停不淡出，B 最後 3s 淡出約 6 dB。

**選曲方向**：輕快但**沒有強拍的 lo-fi / acoustic / 兒歌感**器樂。有鼓點的曲子會逼你卡拍，和這個模板衝突。

## 5. 色調

逐幀 RGB 統計（每支取 96–110 幀）：

| 指標 | A（台北·室內/城市/美食） | B（名古屋·雪地） |
|---|---|---|
| 亮度均值 | 0.427 | **0.500** |
| 亮度 p5 / p99 | 0.076 / 0.946 | 0.097 / 0.914 |
| 對比 (p95−p05) | 0.669 | **0.710** |
| 飽和度均值 | **0.301** | 0.214 |
| **R−B** | **+0.080（暖）** | **−0.048（冷）** |
| 陰影偏色 | R+0.016 G−0.016 B±0 | R−0.004 G−0.015 **B+0.019** |
| 中間調偏色 | **R+0.057 G−0.011 B−0.046** | **R−0.034 G−0.008 B+0.042** |
| 亮部偏色 | R+0.046 G−0.006 B−0.040 | R−0.020 G±0 B+0.020 |

**共通規則（不分主題）：**

1. **陰影提亮不壓死**：p5 在 0.076–0.097，p1 也還有 0.018。**絕不 crush 到 0**。
2. **亮部收住不爆**：p99 ≤ 0.95，沒有大面積 clipping。
3. **對比 0.67–0.71**（p95−p05），比原生手機素材略高但不誇張。
4. 偏色**主要下在中間調**，陰影／亮部的偏移量只有中間調的 1/3–1/2 → 是「色溫偏移」不是「split toning」。

**兩個 preset：**

| | `warm`（城市／室內／美食／親子） | `cool`（雪地／海／清晨／戶外） |
|---|---|---|
| 色溫 | 中間調 **R +0.06 / B −0.05** | 中間調 **R −0.03 / B +0.04** |
| 飽和 | ×1.15（目標 0.30） | ×0.95（目標 0.21） |
| 曝光 | 目標亮度均值 0.43 | 目標亮度均值 0.50 |
| 陰影 | lift 至 p5 ≈ 0.08 | lift 至 p5 ≈ 0.10，**帶藍 +0.02** |
| 對比 | 0.67 | 0.71 |

> **色調是跟著段落主題走的，不是全片一條 LUT。** 同一支片如果有雪地也有室內晚餐，應該分段套不同 preset。

### 7.3 Remotion 元件（`remotion/src/style.tsx`）

| `Captions` / `CaptionItem` | 四層字幕。層預設：chapter `[0.5,0.19]` 5.5%、main `[0.5,0.72]` 5.8%、translit `[0.5,0.785]` 5.0%、emphasis `[0.5,0.45]` 11.5% |
| `StrokeText` | 描邊字。**疊兩層 div**（底層 `WebkitTextStroke`、上層填色），不用單層描邊——單層會從字身內側吃掉筆畫，中文會糊 |
| `anim: "pulse"` | `1 + 0.12*sin(2π·frame/(0.65·fps))`，對應樣本實測的 0.65s 週期 ±12% |
| `LocationBadge` | 米白圓角膠囊，primary 橘 `#E2761B` / secondary 深褐 `#5A3A1B` |
| `PolaroidPhoto` | 米白紙 `#F2F0EB` 鋪滿 + 照片旋轉 + 投影，照片不動 |
| `GradeWrap` | CSS `filter` + `soft-light` 疊色。**不用 SVG feColorMatrix**，那個在影片上會逼 Chrome 走軟體光柵，render 慢很多 |

### 7.4 字幕文字從哪來，剪點從哪來

`work/transcript.json` 是**草稿，不是成品**——時間碼和文字都不能直接用。
L1/L2/L4 的文案是創作性的，由 Claude 在 `script.md` 階段寫、使用者定案（hard rule 4）；
逐字稿的用途是「這一段大概有人講了什麼」，用來挑素材。

> **逐字稿的文字要當中文讀過一遍才能當字幕。**
> 溪頭實例：`small` 把一句話聽成「你家都只有拍到你的手而已」，照抄進字幕，
> 使用者一眼看出「語意很不通順」——「你家」是誤聽，正確是「都只有拍到你的手」。
> 小孩講話＋雨聲的辨識率本來就低（TASKS Phase 1 已記錄），
> **貼進 `captions` 前每一句都要自己讀過**，不通順的就改寫或丟掉。

> **Whisper 的段落時間碼不能直接當 in/out。**
> 溪頭實例：`small` 模型把「哇 現在又起霧了」標成 `902.23–907.68`（5.4s 的合併段落），
> 但 RMS 包絡顯示實際說話在 **906.45–907.70**。照逐字稿剪 `902.2–904.9`，整句話完全沒剪到。
> 同一支片還有三處差 0.2–0.9s 被截尾（爸爸救命喔 / 一二三 / 加油）。
> 小孩講話、風雨聲、長片，這種偏移會更嚴重。

**剪點一律用音訊包絡定。** 做法：對候選窗口抽 16k 單聲道，算 0.05s 的 RMS，
取 `max-16dB` 當門檻找連續發聲區間，再往前後各留 0.2–0.3s 當呼吸。
開場靜音同理——找語句**之間**的天然停頓（溪頭是「一二三」4.55 與「走」5.00 之間），
把 `silence` 放進去，聽起來才像刻意留白而不是把話切斷。

## 8. 一句話總結

**快切、零轉場、不卡拍、字幕當主角、色調跟主題走。**

節奏由「鏡長交錯 + 同鏡跳接」製造，不是由轉場或音樂節拍製造；
資訊由四層字幕承載，畫面只負責好看；
開場 2.5 秒內一定要有鉤子（懸念 + 靜音，或直接上最美畫面）。
